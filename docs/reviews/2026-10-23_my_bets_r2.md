VERDICT: REVISE

Summary: The amendment fixes what my last review asked for. A void leg now waits for every leg. A bet with an unidentified leg is never graded. One grade is written per `bet_id`. Unreadable money fields are skipped. The Protected rule works on the twin fixture. Each change has a test that can fail. Two major problems remain. First, opening the pairing window to "36 hours before the log time, any status" lets a slip pair silently with a different game between the same two teams. That is a guess, which rule 6 forbids. My first review missed this risk, so I lead with it as a correction. Second, the principle the amendment uses for unidentified legs ("counting its losses but never its wins would bias the record") is not applied to void legs. Bets with a void leg still enter the net only when they lose.

Correction to my previous review: checklist item 2 there called leg identification "exact". That was wrong. Even the original code (forward window, active markets only) would pair a bet logged after its game with the next game of the same matchup, if that game resolved within 36 hours. The amendment widens this risk and now invites logging after the games. See finding 1.

[severity: major] /Users/quis/.worktrees/sports-edge-mybet/sports_edge/rate.py:144-145, /Users/quis/.worktrees/sports-edge-mybet/sports_edge/mybet.py:25,59, spec /Users/quis/.worktrees/sports-edge-mybet/docs/specs/my_bets_spec.md:114-118 — A slip carries no date. Pairing picks the single event between the two teams whose `resolve_by` falls in (log time − 36 h, log time + 36 h]. If the game actually bet on falls outside that window, and a later or earlier game between the same teams falls inside it, the slip pairs uniquely with the wrong game.
   - Example: an NBA or NHL playoff Game 1 resolves Sunday 03:00Z. The owner logs it Monday 16:00Z. The window is Sunday 04:00Z to Wednesday 04:00Z. Game 2 (Tuesday 03:00Z) is the only fitting event.
   - All moneyline legs get Game 2's tickers. Every player leg follows too, because its key comes from the paired game (mybet.py:73). The bet is then graded on Game 2's results, and the command says "Identified all N legs".
   - NHL home-and-home sets, NBA two-game sets and every playoff series produce this case.
   - test_mybet.py:211-216 covers only the case where both games are in the window, which correctly refuses.
   - Fix (spec first): refuse a game when the `markets` table holds another game event between the same two teams, in any status, within a wider span such as ±7 days of the candidate. Alternatively, require a `date YYYY-MM-DD` line on the slip. Either way, print each paired event ticker (it contains the date) in the command output so the owner can see it. Add a test where the bet's game resolved 37 hours before logging and the rematch resolves 12 hours after, expecting not identified.

2. [severity: major] /Users/quis/.worktrees/sports-edge-mybet/sports_edge/grader.py:493-500, spec /Users/quis/.worktrees/sports-edge-mybet/docs/specs/my_bets_spec.md:124-126 — A bet with a void (`scalar`) leg enters "settled" and the net only if it lost.
   - [no, scalar] is graded lost at −cost and counted. [yes, scalar] is `void_leg` with blank dollars and left out of the net.
   - That is the same outcome-dependent selection the amendment removed for unidentified legs. It biases the net toward losses in proportion to how often legs are voided (player props on players who don't play are a likely source).
   - The same mechanism also catches legs whose settlement never reaches the table. Example: a void that Kalshi reports with a result other than `scalar`, which `settlement_row` (snapshot.py:115) drops. Such a bet gets graded lost if another leg lost, and stays "open" forever if every other leg won.
   - The spec's "`scalar` (Kalshi's stored value for a void)" is not cited to docs/sources/.
   - Fix (spec first): grade only once every leg has settled. All yes is won. Any scalar is `void_leg`, out of the net, even if another leg lost. Otherwise lost. A bet with a leg that never settles then stays open whether it won or lost. Also count "open past due" in the grader line (every leg's `resolve_by` more than, say, 3 days ago, still open), so a missing settlement is visible (rule 8). Test [no, scalar] → `void_leg`.
