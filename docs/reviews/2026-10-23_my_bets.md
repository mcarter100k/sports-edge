VERDICT: REVISE

Summary: The change stays separate from the evidence path. It writes only `data/my_bets.csv` and `data/my_bet_grades.csv`, both through `ledger.append_rows`. It reads nothing from the shadow ledger, shadow grades, markouts, the pick bet log or the stage. The leg-identification rule refuses rather than guesses. Two settlement problems need fixing before merge. First, a bet can be graded `void_leg` before its other legs have settled, and because each bet is graded only once, a later losing leg is never recorded. Second, the spec lets a bet with an unidentified leg settle as lost but never as won. On live data every NBA player leg is currently unidentified, so the morning line's "settled N, ±$X" will lean toward losses.

Findings:

1. [severity: major] /Users/quis/.worktrees/sports-edge-mybet/sports_edge/grader.py:475-476 — A bet is graded `void_leg` as soon as any one leg settles as something other than yes or no, even while other identified legs are still unsettled. Lines 462-463 then skip any bet that already has a grade, so the result can never change. Example: leg E settles void tonight, leg F is still open, and the bet is written as `void_leg` with blank dollars. Tomorrow F settles no. The bet really lost (a combo loses when any remaining leg loses), but the loss of its cost never reaches the record. The spec table (/Users/quis/.worktrees/sports-edge-mybet/docs/specs/my_bets_spec.md:76) says "and none lost". With one grade per bet, that can only mean once every identified leg has settled. The test at /Users/quis/.worktrees/sports-edge-mybet/tests/test_mybet.py:136 only covers "E void, F yes", so the bug is never exercised. Fix: grade `void_leg` only when every identified leg has a settlement and none is `no`. Add a test with E void and F open, then F no on the next run, expecting `lost`.

2. [severity: major] /Users/quis/.worktrees/sports-edge-mybet/sports_edge/grader.py:473-474, 495; /Users/quis/.worktrees/sports-edge-mybet/sports_edge/slate.py:393; spec /Users/quis/.worktrees/sports-edge-mybet/docs/specs/my_bets_spec.md:82-84 — Which bets count as settled depends on their outcome. A bet with an unidentified leg is counted (lost, minus its cost) when an identified leg loses. The same bet is never counted when it wins, because it is "can't settle" forever. Its losses therefore enter the morning "settled N, −$X" while its wins never do. This is not a corner case. The Gate 2 record (/Users/quis/.worktrees/sports-edge-mybet/docs/validation_log.md:1254-1263) shows every NBA player market listed twice (`KXNBAPTS` and `KXNBAPTSPROT`), so no player leg is ever identified today. Each slip with a player leg can therefore only ever be counted as a loss. The test pins this behaviour: `stuck_lost` is included in the +$75.00 at /Users/quis/.worktrees/sports-edge-mybet/tests/test_mybet.py:139,146. Fix (spec first): keep lost bets with unidentified legs out of `settled` and the net, and show them separately, e.g. "(N lost with legs not identified, −$Y)". Alternatively, settle only bets whose legs are all identified.

3. [severity: minor] /Users/quis/.worktrees/sports-edge-mybet/tests/test_mybet.py:21-48, 81-96 — The test fixture leaves out the `KXNBAPTSPROT` twin events that live Kalshi lists. So "every leg of the owner's real slip is identified exactly" passes on a market set that live data contradicts: live, 5 of 9 legs were identified (validation_log.md:1246-1247). The test at line 99 adds a duplicate inside the same event. It does not cover the real case: a second event that shares the game key and has the same event title. Fix: add the twin event to the fixture and assert that player legs are refused. When the owner decides which series an unmarked leg means, that rule needs a spec amendment and its own test.

4. [severity: minor] /Users/quis/.worktrees/sports-edge-mybet/tests/test_mybet.py:136,140 against /Users/quis/.worktrees/sports-edge-mybet/sports_edge/snapshot.py:115 — The void path is tested with result `"void"`. `settlement_row` never stores that value: it keeps only `yes`, `no` and `scalar`. In production, `scalar` is the only result that can reach the void path. If Kalshi marks a voided leg any other way, the bet is shown as "open" forever (rule 8). Fix: test with `"scalar"`, and say in the spec which result values count as void.

5. [severity: minor] /Users/quis/.worktrees/sports-edge-mybet/sports_edge/grader.py:519 and 472 — `settle_my_bets` runs inside the grader's main try block, before the run summary is recorded. A malformed row in `my_bets.csv` (blank cost, missing field) would make `Decimal(...)` raise. The whole grader run is then recorded as failed, the shadow report and the shadow counts in `job_runs` are lost, and the morning shows "grader failing". The file is append-only, so the bad row can never be removed, and the grader would fail every night. Fix: handle each bet on its own. Skip a malformed row and count it loudly in the report line, or run the my-bets step after the summary is recorded and report its failure separately.

6. [severity: minor] /Users/quis/.worktrees/sports-edge-mybet/sports_edge/slate.py:393 and /Users/quis/.worktrees/sports-edge-mybet/sports_edge/grader.py:503 — With nothing settled, the lines still print a dollar figure. Gate 2 observed "Your own bets: 1, settled 0, +$0.00. (1 can't settle)" (validation_log.md:1249). That is a zero from no observations (rule 8). Fix: leave out the dollar figure when settled is 0.

8. [severity: minor] /Users/quis/.worktrees/sports-edge-mybet/sports_edge/mybet.py:151-174, 182 — Legs are identified once, when the bet is logged, and never retried. A bet logged too early, or after the game ends, keeps unidentified legs permanently, which feeds finding 2. Fix: either say in the spec when to log, or have the grader re-run the same deterministic rules on blank legs, recording the new tickers in a separate append-only file.

Checklist:

1. Evidence separation — No issue found in the code. Every write in `mybet.py` goes to `config.my_bets_path()` through `ledger.append_rows` (mybet.py:187). The grader writes only `config.my_bet_grades_path()` (grader.py:483). `my_bets_summary` reads only those two files (grader.py:489-490). `stage`, `paper_results`, `bets_report`, `taken_bets` and the slate's stage line (slate.py:173) read no my-bets file. In the diff, `settlements` is the only database table read by the new code; nothing new writes to the database. One indirect link: the my-bets step can make the grader evidence job fail (finding 5). The tests do not check every protected file (finding 11).

2. Never guess a leg — The rule is exact, and both zero and two candidates give "not identified":
   - Games pair through `rate.pair_games` (exactly one fitting event, ambiguous orientation rejected; rate.py:149-160).
   - Moneyline legs take that pairing's market for the team (mybet.py:162-164).
   - Player legs need an exact `yes_sub_title`, an event ticker ending in the game key, and an event title ending ": <stat>" ignoring case (mybet.py:169-173). "Total Points" cannot match ": points".
   - Two candidates give None (line 173); this is tested within one event (test_mybet.py:99-108). Live, the `KXNBAPTS`/`KXNBAPTSPROT` twins also give None, which is correct.
   - Remaining risk: the rule does not pin the series. If only one of the twin series were in the `markets` table, it would be taken without the owner's series decision (findings 3 and 8).

3. Settlement correctness —
   - Lost when any identified leg settled `no`, with −cost: correct (grader.py:473-474).
   - Won only when every leg is identified and settled `yes`, with payout − cost: correct (line 477-478).
   - A bet with an unidentified leg is never graded won: correct.
   - Void is wrong: graded too early and frozen (finding 1).
   - Each bet is graded once, using the `bet_id` set from the grades file (line 462-463); the re-run is tested (test_mybet.py:148-149). Settlements has one row per ticker (store.py:47), so lookups have a single answer.
   - `graded_utc` uses `iso_z`. `logged_utc` is UTC with Z, and `logged_pt` shows the zone (tested, test_mybet.py:91).

4. Spec-first and spec agreement — The spec commit 251e475 came before the code commit b98eba2 (reflog lines 3-4). The code matches the spec's columns, `bet_id` rule, lost/won rules, file names, morning wording and amendments, with these exceptions:
   - the void timing (finding 1);
   - the payout > cost rule, which is not in the spec;
   - exit code 2 is not guaranteed for every unreadable input (finding 10);
   - "logged twice" is not tested.
   The spec itself causes the bias in finding 2.
