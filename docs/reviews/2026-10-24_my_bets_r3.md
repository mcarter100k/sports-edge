1. [severity: minor] /Users/quis/.worktrees/sports-edge-mybet/sports_edge/mybet.py:27,60-71,81; spec /Users/quis/.worktrees/sports-edge-mybet/docs/specs/my_bets_spec.md:174-178 — The heading "Never the wrong game of a matchup" claims more than the code does.

Checklist:

1. Finding 1 (wrong game of a matchup)
   - What it covers: `has_rematch` uses the paired event's own `max(resolve_by)` (mybet.py:63) and any status (no status filter). It looks both before and after (BETWEEN when ± 7 d, line 69-70) and counts only `competition_scope = 'Game'` events, as `pair_games` does.
   - Refuse only: it can only remove a pairing (line 81), never add one. Refused games are left out of "Games paired".
   - Not closed: the 5.5-day limit and the single-series check (finding 1).
   - Wrong refusals: MLB series, playoffs, home-and-home sets and relisted events will all be refused. That matters for usability but never picks a game (finding 4).
   - Soccer `TIE`: three-market events never pair (rate.py:153-154), so the set comparison is never reached for them. A superset comparison would be safer.
   - Market storage: snapshot upserts every market of an event together (snapshot.py:132-141), so a part-stored event that would break the comparison is unlikely.

2. Finding 2 (void bias)
   - Grading: a bet enters won, lost or void only after every leg has a stored settlement (grader.py:504). Void is decided before lost (508-511), whatever the other legs did. An unidentified bet is never graded (495).
   - Outcome-dependent selection in code: none found. A leg that never settles keeps the bet open whether it won or lost. The only remaining selection is the owner's choice of what to log after the games (finding 5).
   - Open past due (grader.py:531-542) is right: it takes the `resolve_by` of every leg (max), requires every leg's market to be present (count equals distinct legs), and uses more than 3 days. A leg with a null `resolve_by` is ignored by `max`, which leans towards flagging, an acceptable direction.
